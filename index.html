About Me

저는 아날로그 방식의 복잡한 업무 프로세스를 논리적인 시스템 구조로 전환하여, 데이터 기반의 운영 환경을 만드는 서비스 기획자입니다.

현대퓨처넷 프로젝트에서는 수기 문서와 엑셀에 의존하던 협력사 계약 및 캠페인 운영 프로세스를 100% 디지털 전환(DX)했습니다. 이 과정에서 제 역할은 단순한 기능 기획을 넘어 데이터가 오류 없이 흐를 수 있는 체계를 설계하는 것이었습니다. 15개 매체사의 상이한 신청 양식을 통합하기 위해 자유로운 입력 대신 규격화된 셀렉트 방식의 다이나믹 폼 빌더를 도입해, 시스템 시작 단계에서부터 데이터 정합성을 확보하고 정산 시 발생할 수 있는 휴먼 에러를 원천 차단했습니다.

데이터 엔지니어는 아니지만, 데이터가 가치 있게 쌓이도록 비즈니스 룰을 정의하는 데 강점이 있습니다. 파편화된 업무 이력을 시스템 내 데이터 자산으로 바꿔온 경험을 바탕으로, 안정적이고 체계적으로 확장 가능한 서비스 설계를 제시합니다.

  • 통합 — 계약부터 정산까지 전 과정을 단일 워크플로우로 연결
  • 유연성 — 셀렉트 기반 서식 조립형 다이나믹 폼 빌더로 신규 매체사 즉시 대응
  • 정확성 — 계약 DB·발송 로그 API 연동으로 수기 대조 제거, 정산 데이터 정합성 100% 확보

종이 계약서 기반 프로세스를 온라인화해 문서 관리 리스크를 제거하고 계약 이력을 DB化했으며, 정산 데이터 대조 업무를 자동화된 API 연동으로 대체했습니다.

  • 업무 파편화 및 이력 관리 부재 — 전화·메일로 소통 채널이 분산되고 계약서를 수기로 관리해, 업무 히스토리 추적이 불가능하고 담당자 부재 시 업무 연속성이 끊어지는 리스크가 있었습니다.
  • 수기 기반의 비효율적 캠페인 운영 — 15개 매체사별로 상이한 신청 양식을 수기 문서로 주고받아, 신규 매체사 입점이나 양식 변경 시마다 시스템을 새로 코딩해야 하는 경직된 구조였습니다.
  • 정산 프로세스의 불투명성 — 계약 조건과 발송 데이터가 매칭되지 않는 수동 세금계산서 발행 방식이라, 증빙을 위한 데이터 대조에 막대한 리소스가 들고 휴먼 에러 가능성이 컸습니다.

  • 상담 서비스 플로우 — 상담 시작부터 AI 챗봇/콜봇 응답, STT·NLP·DM(대화 의도 파악) 처리, 응답 실패 반복 시 상담사 연결까지 전체 대화 흐름을 시퀀스로 설계해 예외 케이스까지 명확히 정의
  • Backoffice 화면 설계 — 메뉴 서비스 관리(시나리오·데이터 맵핑)와 AI 브릿지(기본/기타 프롬프트 설정, 데이터 연동 메소드, 챗봇 연동 설정) 화면을 기능 단위로 와이어프레이밍
  • 요구사항 정의서(PRD) — 안내 멘트, 메뉴 시나리오, 코드 관리 등 AI 상담 업무에 필요한 요구사항을 유형·도출단계·제약사항별로 정리해 설계 방향성을 구체화

회고

"AICC 서비스에 대한 서비스 플로우 분석을 통해 전체적인 흐름을 파악하며, 서비스에 대한 이해도를 높일 수 있었습니다. 계약 전 사전 기획 단계였지만, 복잡한 AI 상담 로직을 명확한 화면 설계로 구체화하는 경험을 쌓았습니다."
