걷기 리워드 앱 구축 (신발 브랜드)

걷기 활동에 따라 마일리지를 지급하고 브랜드 공식몰 적립금으로 전환해 주는 하이브리드 앱(iOS·Android)과 웹 관리자를 기획하고 PM으로 이끌고 있습니다. 마일리지가 실제 적립금으로 바뀌는 구조였기 때문에, 어떤 걸음을 정상적인 활동으로 인정할지에 대한 기준을 세우는 것이 가장 중요한 과제였습니다.

  • 비정상 활동 판정 — 장시간 위치 이동이 없거나, 비정상적인 속도로 이동하거나, GPS 수신이 끊긴 상태를 비정상 활동으로 정의하고, 이 상태가 지속되면 알림 후 산책을 자동 종료하는 정책 설계
  • 체크포인트 기반 완주 판정 — GPS 위치가 튀는 현상 때문에 실시간 경로 이탈률로는 완주를 공정하게 판정할 수 없어, 구간별 체크포인트 통과를 기준으로 판정 방식을 변경. 정확도가 낮거나 비정상 속도로 기록된 위치값은 보류한 뒤 다음 위치로 경로를 보정
  • 운영 정책 명문화 — 산책 일지 작성 횟수, 마일리지 유효기간과 소멸 주기처럼 기준이 모호하면 운영 중 혼선이 생길 수 있는 규칙을 오픈 전에 명문화

주요 업무

  • 만보기, GPS 기반 산책 코스·완주 인증, 산책 일지, 마일리지, 챌린지, 공식몰 SSO 연동 기획
  • 핵심 MVP 우선순위 선정으로 개발 범위 조율
  • QA 이슈 취합 및 고객사·개발팀 조율

제조 생산 기업 쇼핑몰 구축

제조 생산 기업 쇼핑몰 구축 프로젝트의 기획 단계를 전담했습니다. 세부 옵션이 많은 상품과 단일 상품을 함께 판매하는 구조에서, 운영자가 상품·주문·정산을 헷갈리지 않고 다룰 수 있는 규칙을 정의하는 데 집중했습니다.

  • 옵션 상품 · 단일 상품 관리 — 세부 옵션 조합이 많은 상품과 단일 상품을 하나의 관리 체계에서 다룰 수 있도록 상품 구조와 등록 규칙을 정의
  • 정산 · 배송 — 상품 특성에 따라 달라지는 배송 방식과 정산 기준을 주문 단위에서 일관되게 처리하도록 설계
  • 상품 · 결제 통계 — 운영자가 판매와 결제 현황을 확인할 수 있는 통계 기능 기획

주요 업무

  • 세부 옵션 상품 및 단일 상품 관리, 정산, 배송, 상품·결제 통계 기능 기획
  • 기획 산출물 작성 완료 및 개발 단계 진행 관리

현대퓨처넷 협력사 포털 & TMS 시스템 구축

종이 계약서·메일·엑셀로 분산된 협력사 계약, 캠페인 신청, 정산 업무를 통합 플랫폼으로 디지털 전환한 프로젝트입니다. 15개 매체사의 서로 다른 신청 양식을 통합하면서, 자유 입력 대신 사전 정의된 항목을 선택해 조합하는 셀렉트 방식을 고집했습니다. 입력 단계에서부터 데이터를 규격화해야 이후 정산에서 발생할 휴먼 에러를 원천 차단할 수 있다고 판단했기 때문입니다.

  • 다이나믹 서식 엔진 — 15개 매체사별 상이한 신청 양식을 셀렉트 기반 서식 조합 방식으로 표준화해, 신규 매체사가 추가되어도 개발 없이 운영자가 서식을 구성
  • 정산 자동화 — 계약 DB 단가와 발송 데이터를 매칭한 자동 정산 로직, 1:N 청구서 일괄 생성, 세금계산서 API 연동 설계
  • 권한 정책 — 관리자·사용자 역할별 메뉴 및 데이터 접근 권한 정책 수립

종이 계약서 기반 계약 프로세스를 온라인화해 계약 이력을 DB화했고, 신규 매체사 추가 시 개발 없이 운영자가 서식을 구성할 수 있는 구조를 마련했습니다. 변경 관리 위원회(CCB) 운영으로 고객사·국내·해외 개발 조직 간 의사결정 체계를 정립했습니다.

프로젝트 상세 보기 (배경·화면 설계·트러블슈팅·회고)

배경 및 Pain Point

  • 업무 파편화 및 이력 관리 부재 — 전화·메일로 소통 채널이 분산되고 계약서를 수기로 관리해, 업무 히스토리 추적이 불가능하고 담당자 부재 시 업무 연속성이 끊어지는 리스크가 있었습니다.
  • 수기 기반의 비효율적 캠페인 운영 — 15개 매체사별로 상이한 신청 양식을 수기 문서로 주고받아, 신규 매체사 입점이나 양식 변경 시마다 시스템을 새로 코딩해야 하는 경직된 구조였습니다.
  • 정산 프로세스의 불투명성 — 계약 조건과 발송 데이터가 매칭되지 않는 수동 세금계산서 발행 방식이라, 증빙을 위한 데이터 대조에 많은 리소스가 들고 휴먼 에러 가능성이 컸습니다.

설계 개념도

화면을 설계할 때 기반이 된 정보구조(IA)와 다이나믹 서식 처리 로직을 다이어그램으로 정리했습니다. 이미지를 클릭하면 원본 크기로 열립니다.

정보구조도(IA) 다이나믹 서식 렌더링 플로우
  • 메뉴 구조(IA) — 계약 관리(서식 설정·입력 항목 관리) / 캠페인 신청 관리(서식 설정·확정서 설정) / 정산 관리 / 커뮤니케이션(업무 코멘트·전자결재) / 시스템 관리(관리자·권한·감사)로 서비스 영역을 구조화
  • 다이나믹 서식 렌더링 규칙 — 계약 유형(매입/매출), 매체사 유형(15종)에 따라 입력 항목 관리에 등록된 항목을 셀렉트 방식으로 조합해 서식을 구성. 매체사·메시지 유형 선택 시 최신 버전 서식이 실시간으로 자동 호출되도록 설계해 오입력 방지
  • 권한 및 보안 정책 — 슈퍼/일반/서포트 어드민으로 메뉴 접근권한 및 승인·반려 등 업무 처리 권한을 차등 설계, 대표/서브 ID 계정 구조로 데이터 열람 범위를 지점 단위까지 제한
  • 정산 처리 플로우 — 확정 서명 완료 캠페인 기준으로 정산 데이터를 누적하고, 동일 사업자·세금계산서 이메일 기준으로 다건 청구서(1:N)를 일괄 생성한 뒤 증빙 파일과 자동 연동
  • 요구사항 정의 프로세스 — RFP 분석 → 현업 담당자 인터뷰 → 요구사항 정의서 작성 → 요구사항 ID·화면 ID를 대조하는 추적표로 변경 이력까지 관리

트러블슈팅 — 변경 관리 위원회(CCB)

Client(현대), On-shore(국내 기획/서버), Off-shore(베트남 개발) 3개 조직이 얽힌 복잡한 협업 구조에서, 발생한 이슈를 주간·월간 회의로 수집하고 변경 관리 위원회(CCB)에서 영향도(공수·일정·비용)를 분석해 승인/반려/보류를 결정하는 프로세스를 운영했습니다. 이를 통해 이해관계자 간 의사결정 체계를 효율화하고, 논의 이력을 Teams·Confluence에 기록해 추적 가능하게 관리했습니다.

이커머스 상품 및 정기구매 시스템 고도화 (리만코리아 공식몰)

일반·사업자 회원별로 다른 구매 조건을 가진 쇼핑몰에서, 회원 유형별 차등 구매 로직과 정기배송 Front·Back Office를 기획하고 CRM 기반 정기구매 관리 프로세스를 설계했습니다. 자동결제 등록 여부, 결제일, 회차 건너뛰기처럼 운영 중 혼선이 생기기 쉬운 정기구매 예외 규칙을 화면 단위로 정의했습니다.

  • 회원 유형별 구매 정책 — 비회원·일반·사업자 회원별 입력 항목, 주문 플로우, 가격·포인트 적용 기준을 분리 정의
  • 정기구매 예외 규칙 — 자동결제 미등록 상태 분기, 결제 카드 교체, 회차 건너뛰기 제한 등 예외 케이스를 명문화
  • 공통 IA — 국내 운영 모델을 기반으로 글로벌 쇼핑몰 공통 IA(Common IA) 가이드라인 수립

국내 운영 모델을 기반으로 글로벌 쇼핑몰 공통 IA(Common IA) 가이드라인을 수립했습니다.

상품 등록 가격 · 포인트 설정 상품 리스트 배너 정기구매 상품 추가 팝업 결제 정보 변경 팝업 마이페이지 정기구매 관리

  • 가격/포인트 설정 — 판매가·Point·BP·SP 등 다중 포인트 체계와 회원 등급별 할인율을 하나의 화면에서 설정하도록 구성, 구매 가능 기간·주문수량 제한까지 포함
  • 상품 리스트 배너 — 대표 이미지 + 연관 상품 그리드를 한 화면에서 관리하며 프로모션 배너를 영역 하단에 배치해 마케팅 확장성 확보
  • 정기구매 상품 추가 팝업 — 브랜드/카테고리 검색 → 옵션 선택 → 담기 → 선택 목록 확인 → 총 합계 자동 계산까지 하나의 팝업 안에서 완결되는 플로우로 설계해 이탈 없이 상품 구성을 마치도록 유도
  • 결제 정보 변경 팝업 — 자동결제 미등록/등록 상태를 분기하고, 카드 최대 5개 등록·결제일 지정(2~25일)·정기구매 카드 교체 시 확인 Alert까지 예외 케이스를 세밀하게 설계
  • 마이페이지 정기구매 관리 — 배송지·결제수단 미등록 상태의 안내 문구, 이번 달 건너뛰기(최대 2회 제한), 즉시결제, 상품 더 담기 등 회차 단위 관리 기능을 설계
  • 회원 유형별 분기 — 비회원/플래너 회원/커스터머 회원 각각의 기본 정보 입력 항목과 주문 플로우를 분리 설계해 회원 등급별 데이터 정합성 확보
